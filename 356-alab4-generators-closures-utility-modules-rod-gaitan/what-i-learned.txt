1. Generators and yield
A generator produces values one at a time, only when asked (lazy evaluation), so it saves memory.
A function containing yield returns a generator object when called. The body doesn’t run until you iterate.
print(fun(10)) shows <generator object fun at 0x...>, not the numbers. To get values, use a for loop, list(...), next(...), or print(*fun(10)).
return i hands back a single int, and looping over an int gives TypeError: 'int' object is not iterable. You only see that error when something actually iterates the result.
next() raises StopIteration when the generator is empty, and a generator can only be consumed once.
range(10) is its own type that prints as range(0, 10). It isn’t a generator, though it also produces values on demand.
'yield' outside function is a SyntaxError caused by yield sitting outside a def, often from indentation or a stray line.
2. Comprehensions
Pattern: [expression for item in iterable if condition].
The expression comes first, and a lone if filter goes at the end.
if/else goes at the front, since it transforms every item.
The if should test the loop variable (item), not the whole collection.
Swap [] for () to get a generator expression.
You walked through the progression: for loop, list comprehension, generator expression.
3. Lambda and sorting
lambda x: expression is a small, unnamed one-line function.
sorted(students, key=lambda s: s[1]) sorts by the second item of each tuple.
Lambdas are handy when passed into another call, like the on_interact example.
4. Lists vs. tuples
Lists are mutable. Tuples are immutable, so you replace them instead of editing them.
Tuples suit fixed records, (x, y) pairs, multiple return values, and dictionary keys.
Immutability is not security or an audit trail, but the “never overwrite, append a new record” idea is how change history works.
5. File paths and open()
Windows paths: doubled backslashes ("\\dir\\file"), forward slashes ("c:/dir/file"), or a raw string (r"c:\dir\file"). Linux uses / paths.
Syntax: open(file_name, mode=..., encoding=...). Modes include r, w, a, and x.
You must store the result (f = open(...)) and print the text to see anything.
A relative path depends on the terminal’s working directory, not the script’s location. The reliable fix is Path(__file__).parent / 'README.txt'.
A leading / means the root of the drive.
Always specify encoding='utf-8' for text files. Windows has historically not defaulted to UTF-8, and binary mode takes no encoding.
6. Predefined streams
sys.stdin, sys.stdout, and sys.stderr are open before your program starts.
input() reads from stdin, print() writes to stdout, and errors go to stderr.
sys.stdin.read() takes no prompt, which is why input("Enter name: ") exists.
7. Modules, classes, methods, and attributes
from datetime import date: datetime is the module and date is a class inside it.
Methods need (), like date.today(). Attributes don’t, like .year, .month, and .day. Parentheses depend on what the thing is, not where it’s accessed from.
Use dir(), help(), callable(), and type() to explore what’s available.
Shadowing: naming your own file datetime.py (or time.py, random.py, and so on) breaks the standard library import. Rename the file and delete __pycache__.
8. Other tools
time.sleep(seconds) pauses the program.
calendar.setfirstweekday(...) is a setting that returns nothing, so you print calendar.month(2026, 10) to see its effect.
print(*items), end=" ", and sep=", " control horizontal output.
pyperclip is third-party and needs pip install (use python -m pip with your interpreter).
Big takeaways
No output usually means nothing asked for output. Functions that do something (sleep, close, setfirstweekday) return nothing, so you need print() to see results.
Errors usually depend on context. The TypeError needs a loop, and the FileNotFoundError depends on the working directory.
Read error messages closely. The datetime import error told you the exact cause.
